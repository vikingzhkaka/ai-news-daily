多 Agent 实战三个坑：教程里永远撞不到、真跑起来必炸

一位开发者用 LangGraph + Supervisor 模式搭协作平台后总结出三个只有真跑才会遇到的坑：①成员 Agent 会认错人——多个 Agent 共享一条会话历史时全被打成 assistant，模型以为别人说的话是自己说的，解法是把历史按"当前应答者视角"重写（本人原样／第三方标注来源／派给我的转第二人称）；②知识库别拼进 prompt，封装成工具——让模型自己决定要不要查、查哪个、查几次；③能跑代码的沙箱要由独占进程持有，否则容器泄漏是迟早的事。

落地建议：如果你在搭多角色 AI 流程，先检查"每个角色看到的上下文是不是同一份"。同一份历史喂给不同角色，几乎必然产生身份混淆——这是最被低估、也最便宜就能修的一个坑。
