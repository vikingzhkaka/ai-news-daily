Context Engineering（情境工程）：少即是多，给 Agent 一份「工作说明书」
2026-06-10 那天三路信号同时指向同一方向：两篇 arXiv（2606.10209《Less Context, Better Agents》、2606.09900《Bi-Temporal Memory》）外加 TechCrunch 一篇「记忆工具反而让模型变差」。核心反直觉：Agent 出问题时，反射动作是「给它更多上下文」，但研究指向相反——更干净、更小的窗口在准确率、成本、速度上同时胜出。成熟做法是三层记忆（工作记忆 / 会话压缩记忆 / 外部持久库）+ 到阈值就压缩 + 双时间记忆（事件时间 vs 入库时间）区分「事实何时为真」与「系统何时记下」。
来源：Clawvard / Danilchenko / Anthropic 情境工程指南（2026）2026-06-10
建议：派活前先写结构化 brief（边界 / 可用素材 / 判据 / 何时停下），而不是扔一个开放题。把「上下文到阈值就压缩」做成 Agent 的默认动作，比换更大上下文窗口更省钱也更准。
Harness 工程：生产级 Agent 98% 的代码是「外壳」，不是模型
OpenAI「Harness Engineering」与 Anthropic Claude Code 分析（arXiv:2604.14228）汇出同一结论：生产 Agent 里约 98% 的代码不是模型循环，而是围绕它的外壳——情境管理、权限、校验、子代理委派、工具路由、恢复。LangChain 实证（2026-03）：模型固定在 gpt-5.2-codex，仅靠改 harness，Terminal Bench 2.0 从 Top 30 升到 Top 5（52.8%→66.5%）。模型能力收敛后，harness 质量是持久护城河。七层模型：Agent Loop→情境记忆→持久执行→护栏→人在回路→评估→可观测。
来源：GunBark / BotLearn / AgentsCodex（2026-06-14）2026-06-14
建议：做 Agent 落地时，把精力从「选哪个模型」转到「harness 是否可靠」——加校验循环、加权限门、加 checkpoint 可恢复。Viking 的峰会 Bot 迭代也应沿这条线走：稳定靠 harness，不靠换模型。
